I want to build a production-ready full-stack system called **Paytrixx**, which is a **Payment Router + Tracking Platform**, integrated with an Ecommerce system.

IMPORTANT:
Paytrixx is NOT a payment gateway. It must NEVER directly collect money.
All payments must be processed via Paytm Payment Gateway.

---

# 🎯 CORE OBJECTIVE

Build a system where:

1. A merchant integrates Paytrixx API
2. Paytrixx creates an order internally
3. The system routes the payment to Paytm via Ecommerce backend
4. User pays on Paytm
5. Paytm sends webhook
6. Backend updates order + transaction
7. Paytrixx notifies merchant via callback
8. Paytrixx dashboard shows merchant-wise analytics

---

# 🧱 SYSTEM ARCHITECTURE

Use a **Modular Monolith Backend**:

* Node.js + Express.js

# 🔄 PAYMENT FLOW (STRICTLY FOLLOW)

Step 1:
Merchant calls:
POST /api/payment/create

Headers:

* x-api-key

Body:
{
amount,
currency,
customerDetails
}

---

Step 2:
Backend validates merchant using API key

---

Step 3:
Backend creates:

* Order (status: pending)
* Transaction (status: pending)

---

Step 4:
Backend creates Paytm order using Paytm API

---

Step 5:
Return:
{
orderId,
paymentUrl,
status: "pending"
}

---

Step 6:
User completes payment on Paytm

---

Step 7:
Paytm calls webhook:
POST /api/webhook/paytm

---

Step 8:
Backend MUST:

1. Verify Paytm signature (CRITICAL)
2. Check if order already processed (idempotency)
3. Update:

   * Order.status = "paid"
   * Transaction.status = "success"
4. Store Paytm txnId
5. Log response

---

Step 9:
Backend sends callback to merchant:

POST merchant.callbackUrl

{
orderId,
status: "success",
amount
}

---

# ❗ STRICT RULES

* NEVER mark success before webhook
* NEVER use static QR codes
* ALWAYS verify Paytm signature
* HANDLE duplicate webhooks safely
* USE idempotent logic
* LOG all events
